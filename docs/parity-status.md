## Summary

OpenClicky has the core HeyClicky loop on `main`: a push-to-talk voice turn through the brain, speech-paced 2D drawings and 3D figures, guided walkthroughs, background Codex and Claude Code jobs with connected apps, skills and memory. 61 of 133 rows are `working` and 52 are `partial`. Most `partial` rows are missing secondary behaviour or have never been driven by a person on real hardware; the 17 `missing` rows are mostly onboarding content, characters, proactive features, previews and hand-off. Nothing has been driven by a person through the installed app yet, so the person checks below come before any release.

Changes since the 2 November audit (46 working, 63 partial, 21 missing, 3 wont-build, 59 person):

- **Re-graded up to `working`:** `screen-capture` (a real ScreenCaptureKit capture and JPEG encode ran through `occtl`), `screen-context` (live Accessibility page read of Chrome), `lookup-web-search` (live Brave and Exa searches), `apps-obsidian` (the old OAuth-refresh gap does not apply to a local vault).
- **Re-graded down to `partial`:** `browser-skill`, because parts of HeyClicky's skill (own tab group, batch-first workflow, saved proof screenshots, upload and download rules) can't be written until the tool has those operations.
- **Closed gaps:** the login item is registered and approved (`sfltool dumpbtm` shows `[enabled, allowed, notified]` and `loginItemFirstLaunchHandled=true`); voice lines are metered through `MeteredSpeechOutputClient`; held deferred actions (clipboard, open URL) do come back from `send_to_higher_model`; result cards render agent Markdown links; connector changes rebuild the brain and realtime tools; the notch pins an onboarding invite; the running app serves the loopback MCP endpoint and hosts the browser bridge.
- **Newly found defects:** `openclicky://settings/usage` and `/developer` are refused because `SettingsPageID` lacks those pages; the brain is told `scene3d()` exists when it does not; three Developer flags (`drawing.sounds`, `agents.voice-announcements`, `notch.upcoming-meetings`) switch nothing; `composioToolkits` is never passed; agent job token usage never reaches the usage ledger.
- **Person column (66, was 59):** added for `shell-home`, `shell-settings`, `voice-apple-speech`, `voice-job-reports`, `skills-library`, `skills-active`, `mem-profile` and `hist-conversation`, which each still need a hands-on check in the running app; removed for `screen-capture-variants`, whose remaining gaps are code or key work.

## What works end to end today

- **The installed app.** `/Applications/OpenClicky.app` (built from `6c036f5`, original icon from #60) runs as a menu-bar app; its login item is registered and approved, and it starts the browser bridge and the agents' loopback MCP server (`BrowserBridge/mcp.json`, answered `occtl browser call status`). Show in Dock and clean quits are recorded in `evidence/feat-settings-pages/live-open-check.txt`. A launch at login has not been observed yet.
- **Voice turns through `occtl turn`.** The real turn orchestrator, brain runtime, line narrator, speech player and drawing run with simulated speech-to-text: Haiku plus ElevenLabs reached the first line heard 3.2 s after key up, and five cheap-config turns with real speech recognition had a median of 2.1 s ([latency.md](latency.md)). Barge-in, Escape, cut-off notes and report turns are covered by tests (`voice-orchestrator`, `voice-latency`, `voice-job-reports`).
- **The brain.** `say()` lines stream before the program ends, read rounds work (`web_search` through Brave), prewarm caches 12.1k of 13.6k input tokens and sessions persist and end with a memory note, all live on `claude-haiku-5-5` only (`voice-brain-*`). The OpenAI paths have not run live (no OpenAI key on this Mac).
- **Screen.** `occtl screen capture` did a real ScreenCaptureKit capture (1280x832 JPEG, pointer screen labelled, settle sampler ran) and `occtl screen context` read the front Chrome page through Accessibility on this unlocked Mac (`screen-capture`, `screen-context`). The app path's self-exclusion filter has not been observed live.
- **On-device and cloud transcription.** Apple Speech transcribed a recorded question exactly, and Gemini Live transcription ran live (`voice-apple-speech`, `voice-ears`).
- **Speech-paced 2D drawing and media.** Brain-written programs draw while each line is heard; photos, MapKit places and favicons resolve live; follow-ups edit the same card (`draw-runner`, `draw-generation`, `draw-photos`, `draw-editor`). Guided walkthroughs and draw-to-ask run through `occtl` against live Haiku (`point-guided`, `screen-draw-to-ask`).
- **3D figures.** Figures build and render offscreen in the illustrated and studio looks, ticks run frame after frame in the real engine, and a clicked part became a follow-up turn (`3d-kernel`, `3d-scene-model`, `3d-illustrated`, `3d-studio`, `3d-tick`, `3d-picking`).
- **Background agents.** Jobs ran live on Codex (`codex-cli` 0.165.0) and Claude Code (2.1.314); a Claude Code job on Haiku read a task-asset screenshot, wrote into the Obsidian vault, called a stdio connector and the browser MCP, and its result was told in a live report turn that opened the result card. Routines ran live on Claude Code (`agent-codex`, `agent-anthropic`, `agent-task-assets`, `apps-agent-mcp`, `agent-remote-tasks`).
- **Browser bridge.** The native host, manifests (now refused from translocated copies, #67) and socket transport pass the headless Chrome for Testing end-to-end run; the running app hosts the bridge (`browser-host`, `browser-manifests`, `browser-transport`).
- **Memory, skills and history.** Save, recall of an earlier chat and forget ran live; a skill was created from a brain dump by a Claude Code job and followed by later jobs (`mem-*`, `skills-library`, `skills-active`, `skills-bundled-agent`).
- **Infrastructure.** Provider retries, diagnosis, the usage ledger with limits, diagnostics with secret and transcript scrubbing, and the URL router all ran live through `occtl` (`shell-http`, `shell-usage`, `shell-telemetry`, `shell-url-router`, `voice-provider-diagnosis`).
- **Always-on voice on Gemini.** Gemini 3.8 Live ran live with `capture_screen`, `send_to_higher_model` and drawing; the row stays `partial` because OpenAI Realtime has not run live and nobody has used it on hardware.
